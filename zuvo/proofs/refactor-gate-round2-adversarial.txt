**SEVERITY:** WARNING
**CONFIDENCE:** high
**FILE:** scripts/install-refactor-gate.sh:441-457 (`install_global_dispatch`)
**ID:** install-refactor-gate.sh:441:uncaught-runtimeerror-traceback
**ISSUE:** `file_identity()` raises `RuntimeError` for non-regular files (symlinks, FIFOs), but `install_global_dispatch` never catches it — including the `file_identity(receipt)` call passed as an argument to `refresh_hook` and the race-recheck inside `refresh_hook(path, ...)`.
**ATTACK VECTOR:** If `~/.claude/hooks/.refactor-safety-gate.sha256` is a symlink to a regular file (the `is_file()` guard follows symlinks, so only `is_symlink()` excludes it — but `file_identity` re-checks and raises), or if the hook path is swapped to a symlink between the top-of-function `file_identity(path)` and the recheck in `refresh_hook`, the installer crashes with a raw Python traceback exposing local filesystem paths, instead of the documented graceful "preserved, exit 2" behavior. Any crash before `refresh_hook(path, ...)` also leaves the receipt refreshed state inconsistent with the hook.
**SUGGESTED FIX:** Wrap the `install_global_dispatch` body (or at least the `refresh_hook` calls) in `try/except RuntimeError` and route through the existing `unavailable(...)` path, matching the documented exit-2 contract.

**SEVERITY:** WARNING
**CONFIDENCE:** medium
**FILE:** hooks/refactor-gate-dispatch.sh:47-49 (harness fallback gates)
**ID:** refactor-gate-dispatch.sh:47:harness-symlink-containment-bypass
**ISSUE:** The containment check (`gate.resolve().relative_to(resolved_root)`) is vacuous for the non-cache fallback candidates (`.codex`, `.cursor`, `.gemini`, `.kimi-code`, `.zuvo-plugin`): both `root` and `gate` are resolved through the same symlink chain, so a symlinked harness gate resolves its root along with it and always passes.
**ATTACK VECTOR:** An attacker (or a corrupted dotfile sync tool) who can replace `~/.codex/scripts/refactor-safety-gate.sh` with a symlink to an arbitrary executable gets it exec'd by every git hook in every repository using the stable dispatcher. The cache-scoping added in this diff explicitly protects only `cached=True` roots, yet the code comments suggest symlink escape was a threat model ("A gate symlink must not escape its selected install").
**SUGGESTED FIX:** For non-cached fallback candidates, verify the *unresolved* path is a real file within the (unresolved) parent directory — e.g. reject when `gate.parent != resolved_root` after resolving only the root — or resolve the root first and build the candidate from the resolved root before the containment comparison.

**CONFIDENCE:** low
**FILE:** hooks/refactor-gate-dispatch.sh:44-57 (check-then-exec window)
**ID:** refactor-gate-dispatch.sh:44:toctou-check-exec-symlink
**ISSUE:** TOCTOU between the symlink/digest/recursion validation and `os.execv`: the gate file can be swapped (e.g. replaced with a symlink via `rename`) after `gate.resolve()`, `is_file()`, and the content read, but before `execv`.
**ATTACK VECTOR:** A local process racing the hook can cause `execv` to execute a different binary than the one that was validated. The runbook declares this script "not a security boundary," which limits impact, but the new per-candidate containment checks give false assurance since they cannot be enforced atomically with `execv`.
**SUGGESTED FIX:** Open the gate with `os.open(..., O_RDONLY|O_NOFOLLOW)` once, validate contents via the fd, and execute via `/proc/self/fd/N` (or verify with `os.fstat` + `st_dev/st_ino` match immediately before `execv`).

**SEVERITY:** INFO
**CONFIDENCE:** medium
**FILE:** scripts/install-refactor-gate.sh:451-453 (receipt digest handling)
**ID:** install-refactor-gate.sh:451:receipt-blesses-foreign-overwrite
**ISSUE:** Any digest recorded in the user-writable receipt file `.refactor-safety-gate.sha256` is accepted as "known", allowing the ownership check to bless and overwrite an arbitrary pre-planted hook file whose digest matches the receipt.
**ATTACK VECTOR:** A stale, corrupted, or attacker-planted receipt causes `install_global_dispatch` to take ownership of a file it would otherwise preserve — overwriting it with the dispatcher body. Impact is confined to the same user's trust domain (who could edit the hook directly), so this is primarily an integrity/robustness concern, not privilege escalation.
**SUGGESTED FIX:** When the current hook digest matches only the receipt (not the legacy constants or the current source digest), require an explicit confirmation flag or at least log the overwrite loudly instead of silently refreshing.

SEVERITY: WARNING
CONFIDENCE: medium
FILE: hooks/refactor-gate-dispatch.sh:60
ID: refactor-gate-dispatch.sh:60:symlinked-gate-skipped-failopen
ISSUE: The containment check `gate.resolve().relative_to(resolved_root) != gate.relative_to(root)` also applies to the non-cache fallbacks (`~/.codex/scripts/...`, `~/.cursor/...`, `~/.kimi-code/hooks/...`, `~/.zuvo-plugin/hooks/...`). For those, `root` is `(home/relative).parent`, so a gate that is a symlink anywhere (a dev install linked to a repo checkout, or a dotfile manager) always raises `ValueError`. It is reported as "unavailable gate skipped" and the loop moves on.
ATTACK VECTOR: On a machine where the only gate is a symlinked one, every commit and push fails open with just a warning. The symlink guard was meant to stop escapes from a cache install, but here it turns a legitimate layout into a silent bypass of the safety gate.
SUGGESTED FIX: Apply the escape check only when `cached` is true, as for the `~/.zuvo/current` exemption. For the fixed harness paths, accept the resolved target if it is a regular executable file.

SEVERITY: INFO
CONFIDENCE: medium
FILE: scripts/install-refactor-gate.sh:441
ID: install-refactor-gate.sh:441:receipt-written-after-hook-stale
ISSUE: `install_global_dispatch` replaces the global hook first, then writes the digest receipt through `refresh_hook(receipt, ..., file_identity(receipt))`. If the receipt step fails, the hook is already replaced and the receipt is stale or absent. A receipt that is a symlink or other non-regular file makes `file_identity` raise `RuntimeError`, and this function does not catch it.
ATTACK VECTOR: After a partial failure the global hook holds template digest D1, but the receipt is missing or old, and `known` only contains the legacy digests, the current template digest and the current source gate digest. At the next zuvo release (template D2), the installed hook (D1) is not in `known`. It is classified as a "foreign global hook" and preserved, so the global gate never upgrades again until someone removes it by hand. An uncaught `RuntimeError` may also surface as a traceback instead of the documented clean exit 2.
SUGGESTED FIX: Write the receipt before the hook, or write both in one step and treat a receipt failure as non-fatal. Wrap the `RuntimeError` from `file_identity` in `unavailable(...)`.

SEVERITY: INFO
CONFIDENCE: low
FILE: hooks/refactor-gate-dispatch.sh:31
ID: refactor-gate-dispatch.sh:31:registry-file-order-downgrade
ISSUE: Registry `installPath` records are tried in file order, with no check of scope, enabled state or version, and all of them run before the newest numeric cache version. A stale or project-scoped record for an older version listed first selects that older gate.
ATTACK VECTOR: After an upgrade, a leftover registry record (another project scope, or a disabled or old install whose directory still exists) pointing at an old version wins over the newest cache. An old gate with weaker or buggy rules enforces, or fails open, instead of the current one. This is unlikely to be exploitable by a third party, since the registry is user-owned. It does weaken the "gate follows upgrades" guarantee.
SUGGESTED FIX: Collect all registry candidates that pass the cache-child check. Sort them with the numeric versions (semver-descending, SHA dirs last) instead of trusting file order.
