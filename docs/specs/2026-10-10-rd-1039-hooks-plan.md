## Technical Decisions

- **Refuse rule inline per script** (bash in `rotate-retros`, python in `sanitize-retros`): `retro-appendonly.sh`
  is optional and degrades to no-op stubs, and `sanitize-retros` is Python. Exit **4** = refused by high-water,
  distinct from 3 (lock busy) and 1 (abort). Checked under the lock, before any archive/temp/backup write. High-water
  parse identical to `append-retro:338-339`. No bypass flag; the message points to the runbook (§12, added in Task 6).
- **Lock, high-water and snapshots sit beside the target** (`dirname "$TARGET"`); variable name `RLOCK` kept.
  `sanitize-retros` base dir `ZUVO_HOME` → `ZUVO_DIR` (legacy) → `~/.zuvo`; lock/high-water from
  `dirname(target)`. The mkdir lock stays — flock would not exclude mkdir-lock holders.
- **Rotation lowers the high-water to KEPT and takes a fresh post-rotation snapshot**, both before the `mv`, so
  the newest snapshot never holds archived rows. Old snapshots age out through keep-24. The `.md` arm snapshots
  the log only when it is at or above the high-water. `append-retro` is not modified (its auto-recover only unions
  and adopts strict improvements).
- **Farm hook**: one linear char-walk splitter (implemented as `_scan` + `_take_bodies`) (states cmd / sq / ansi `$'…'` / dq / comment; `$(` and backticks push a
  nested cmd state even inside dq, so a heredoc opened inside `"$(cat <<EOF …)"` is recognised; heredoc openers only
  in cmd state; opener-line remainder kept as command text; unterminated body returned to command text) plus
  `body_subs` for unquoted data bodies (quotes literal; backslash escapes). Shell-fed detection reuses the existing
  opener regexes on the opener line without requiring a newline right after the delimiter. Fast path,
  `nested_has_suite` and segment analysis unchanged. Embedded python uses `\x27`, never a literal `'`.
- **session-start**: only when `CLAUDE_ENV_FILE` is set and stdin is not a tty; bounded read (`read -t 2`, `|| true`),
  id parsed with python `json.loads` and allowlisted `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`; append the exact export line
  if not already present; nothing to stdout; every failure swallowed. `resume` is NOT added to the matcher (it would
  re-inject the router into a context that holds it); a resumed session keeps whatever its env file already holds
  and otherwise gets the honest `-` fallback — a documented limitation in the hook comment, not silently ignored. Codex/Kimi keep the honest `-` fallback.
- **track-includes**: one `_inc_dir=/tmp` assignment used by both the tracker path and the prune
  (`find "$_inc_dir" -maxdepth 1 -type f -name 'zuvo-includes-*.txt' -mmin +1440 -exec rm -f {} +`), run only when this
  session's tracker does not exist yet.
- `ran:unknown` stays out of the skill-facing usage block (append-retro:168 forbids skills from using it).
- Stale mutation plans (`tests/mutation/*.json`) are left alone — not consumed by run-all; regenerate when a scoped
  mutation run needs them.
